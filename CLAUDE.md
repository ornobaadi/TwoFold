# CLAUDE.md — TwoFold

Flutter (Android first) reader with a built-in audiobook player. Read the book, listen to the audio, and always resume at the same page and the same second.

## Source of truth (read before changing anything)

| File | What it decides |
|------|-----------------|
| `PRD.md` | Features F1–F10, key behaviours, success criteria. Scope questions end here. |
| `Architecture.md` | Packages, folder layout, SQL schema, audio flow, progress-saving triggers, gestures. |
| `design.md` | Colours, type, spacing, screens, things to avoid. |
| `phases.md` | Build order. Finish a phase before starting the next. |

If these files disagree, PRD wins on behaviour, design.md on looks, Architecture.md on structure. Record the conflict and the resolution under Decisions below.

## Rules that must not break

- Audio and page position are independent. Page turns never touch audio, audio never turns pages.
- Opening a book never autoplays. Land on restored page + restored time, paused.
- Progress is saved by column-scoped writes (see Decisions), on: every 5 s while playing, pause/stop, every page turn, `AppLifecycleState.paused/detached`.
- One `AudioHandler` for the whole app. Switching books saves the current one first.
- The internet is used only by Find free books (`lib/find/`), and only when the user searches or taps Get. Nothing else opens a connection. No Google Fonts calls; Literata and Inter are bundled assets.
- Design: Folio per `design.md` (paper and ink, serif-led, hairlines, one quiet accent; no Material 3 Expressive shapes, springs or tinted containers): colour roles from `schemeFor`, labels kept on controls, 48 dp touch targets, only Literata + Inter.
- Player bar and reader must never steal each other's touches.

## Skills in `.agents/skills` and how to use them here

- `ui-taste` (`reference/new-work.md`, `polish.md`, `audit.md`): use for building each screen and for the final visual review of each phase. The iOS playbook is not needed until the iOS build.
- `ui-ux-pro-max`: touch targets, contrast, accessibility checks. Its suggestions yield to `design.md`.
- `frontend-design`, `design-taste-frontend`: web-oriented; take only the anti-generic-look principles.

- `android-clean-architecture`: Kotlin-specific; only the layering idea carries over (UI → controller → repo, repo hides sqflite, no UI code in `data/` or `audio/`).
- `no-ai-slop`: use when writing README, store text, and in-app copy.
- `design-mobile-apps` (needs paid API key), `aso`, `seo-audit`, `brag`, `product-launch-video`, `video-edit*`: out of scope for now.

## Build plan

Follows `phases.md`. v1 = Phases 0–4.

0. **Setup:** pubspec packages, fonts, `app/theme.dart` with 3 themes, Android manifest (foreground service, media playback, wake lock, notifications; no internet), folder skeleton.
1. **Player that remembers:** `data/db.dart` + `book_repo.dart` (progress first), `audio_handler.dart`, `player_controller.dart`, temporary test screen. Verify: lock screen, kill app, resume same second.
2. **Library + import:** `importer.dart`, `library_screen`, `book_card`, attach audio, remove book.
3. **Reader:** EPUB (`flutter_epub_viewer`) and PDF (`pdfrx`), location save/restore, page indicator.
4. **2-in-1 screen:** floating `player_bar`, `mini_play_button`, tap-centre toggle, auto-hide 4 s, Listen mode.
5. **Comfort (v1.1):** auto-rewind, sleep timer, skip length, reader settings sheet, chapters.
6. **Polish:** empty states, DRM error, large M4B/PDF test, battery check, release APK (<30 MB).

Testing: unit tests for repo and skip/clamp-across-tracks logic, widget tests for gesture isolation, manual device checks for background audio and force-kill resume.

## Risks to check early

- Package versions: Flutter 3.47.5 / Dart ^3.13.4 are newer than the doc's assumptions. Confirm each package resolves (`flutter pub add`) and that `just_audio` still offers `ConcatenatingAudioSource` (newer versions may favour another playlist API).
- `flutter_epub_viewer` uses a WebView; check swipe pagination vs. the player-bar overlay on a real device.
- Pre-existing `ios/ macos/ linux/ windows/ web/` folders exist although v1 is Android only. Leave them; do not maintain them.

## Decisions

- **Playlist API:** `just_audio` 0.10 deprecates `ConcatenatingAudioSource`. Use `player.setAudioSources(list, initialIndex:, initialPosition:)`.
- **file_picker 13:** the API is static, `FilePicker.pickFiles(...)` returns a list (empty on cancel). `FilePicker.platform` from older docs no longer exists. Single file: `FilePicker.pickFile()`.
- **Progress writes touch disjoint columns:** `BookRepo.saveAudio` and `saveReading` each update only their own columns (insert-ignore, then update, in one transaction) instead of one `INSERT OR REPLACE` of the whole row. A page turn can't overwrite the audio position or the reverse. This refines Architecture.md "Saving progress".
- **Absolute timeline:** the audio handler exposes one position measured from the start of the first track. Notification, lock screen scrubber, UI scrubber and skips all use it; `lib/audio/timeline.dart` maps it to (track, offset).
- **Interruptions:** the player is created with `handleInterruptions: false`. `DuetAudioHandler` pauses on a call or another app's audio and on headphone unplug, ducks on transient duck events, and never resumes by itself (PRD section 6).
- **`just_audio` `play()` future** completes only when playback pauses, so the handler does not await it.
- **Gradle memory:** this machine has 8 GB RAM; keep `org.gradle.jvmargs` at `-Xmx2G`.
- **Builds:** the user builds and installs. Claude runs `flutter analyze` and `flutter test` only, and hands over the build command.
- **Notification permission:** `MainActivity` exposes channel `duet/permissions`; the app asks for `POST_NOTIFICATIONS` at launch on Android 13+.
- **File picking is native:** `MainActivity` channel `duet/files` opens the document picker filtered by MIME type (EPUB/PDF, or audio), opening wherever Android last was, plus a folder picker that lists audio in subfolders. `file_picker` is gone. Android's system picker can't hide folders; it greys out files of other types.
- **Audio is not copied (changes PRD F1):** tracks store persisted `content://` URIs and play from the original location, so importing is instant and uses no space. Moving or deleting the originals makes that audio unavailable, and the reader says so. Book files are still copied because the viewers need a real file. Older imports keep their copies until the book is removed.
- **Same-book reopen:** `loadBook` does nothing if that book is loaded, so returning to a playing book keeps it playing. PRD "never autoplays" still holds: nothing starts playback on open.
- **Resume into the book:** `open_book` in settings is set when the reader opens and cleared when it is left, so after a kill the app returns to the reader (PRD use case 3).
- **Native EPUB reader (replaces `flutter_epub_viewer`, which failed on the user's phone in both its loading modes):** `epub_book.dart` parses the zip and XHTML into blocks in an isolate, `epub_layout.dart` paginates with `TextPainter`, `epub_view.dart` shows them in a `PageView`. CSS is ignored on purpose. Location is `block:char`, stable across font changes. No WebView.
- **EPUB font:** book text is Literata, as design.md asks.
- **Primary buttons are ink, not accent:** design.md reserves the accent for play, progress and selection.
- **Isolates:** spawn from top-level functions only; a closure in a widget method can capture the widget and fail when sent.
- **PDF paging:** a `PageView` of `PdfPageView`s, not `PdfViewer`, for real one-page swipes. No `InteractiveViewer`: it competed with the swipe.
- **No `epubx`:** it pinned `image`/`archive` 3, which held `pdfrx_engine` at a version that does not compile on this Dart. `parseOpf` in `importer.dart` reads title, author and cover with `archive` and `xml`. This replaces the Architecture.md entry.
- **`pdfrx` pinned at 2.6.6:** 2.7+ compiles a C library in a build hook, which breaks `flutter test` on this PC (no desktop C compiler). Below about 2.4.6 does not compile on this Dart. pdfrx still downloads PDFium from GitHub at build time, so the build machine needs internet; the app does not.
- **Short interruptions resume (refines PRD section 6):** a transient focus loss outside a call resumes if it ends within 30 s; calls and other apps' music stay paused.
- **No speech-to-text search:** matching heard words needs a transcript. Offline transcription is too heavy for this app, so search is on the book text, then an estimate moves the audio.
- **Audio chapters:** Nero `chpl` atoms are parsed; QuickTime text-track chapters are not. Without chapters, each audio file is one chapter.
- **No DRM check:** personal app, at the user's request. A file is refused only if no text can be read from it.
- **Material 3 Expressive replaces the paperback look (user request, 2026-11-01):** `design.md` was rewritten. No dynamic colour: the page tint and brand stay predictable, and it would add a plugin.
- **Identity:** app TwoFold, package `com.ornobaadi.twofold`, Dart package `twofold`. A new application id installs as a new app, so nothing migrates from the old `com.example.duet` install.
- **Search no longer offers to move the audio:** the estimate was too rough beside an exact search hit. My places keeps its labelled "close, not exact" moves.
- **Bundled samples:** sample audio ships in the app and is copied to app storage on first launch, so there is something to read and hear before any search (written when the app had no internet at all).
- **Find free books (user request 2026-11-10, replaces "no network permission" and PRD "fully offline"):** in-app search and download from Project Gutenberg (its OPDS feed `/ebooks/search.opds/`; files from `/ebooks/<id>.epub3.images` and fallbacks), the Internet Archive (`advancedsearch.php`, then `/metadata/<id>` for the file list; only pre-1931, never the lent-out `inlibrary` or access-restricted items; EPUB, then a text PDF, never an image-only PDF) and Wikisource (MediaWiki search, then an EPUB made by `ws-export.wmcloud.org`). The privacy policy, store text, README, PRD, Architecture and the Settings line were changed to match. **Play Console's Data safety form must be updated by hand.**
- **Find free books rules:** https only and a fixed host list (`findHosts` in `find/web.dart`), checked on every redirect. One request per connection (`persistentConnection = false`): Gutenberg cut a download short on a kept-alive connection, found in a live test. A dropped download resumes with a Range request, 2 times at most. The User-Agent names TwoFold honestly (`TwoFold/<version> (...)`, kept in step with the app version); never send a browser's, and do not hammer the sites: Gutenberg's robot policy blocks IPs for automated harvesting, so one request per tap, no prefetching. Files must start with the EPUB or PDF signature and stay under 150 MB. Downloads go through the normal importer, so they are copied like any picked file and the temporary download is deleted.
- **Standard Ebooks is not included:** its OPDS search feeds are patron-only (HTTP 401) and its robots.txt disallows `/ebooks/*/downloads/*` for AI user agents. Revisit only if the user wants patron sign-in.
- **Gutendex not used:** a volunteer-run mirror of the Gutenberg catalogue that timed out in testing; Gutenberg's own OPDS feed is used instead.
- **Dev build (user request 2026-11-10):** debug and profile builds use application id `com.ornobaadi.twofold.dev` and the name "TwoFold Dev" (`resValue app_name`; the manifest label is `@string/app_name`). They install beside the Play app with their own data. Profile is signed with the debug key and not shrunk.
- **Folio replaces Material 3 Expressive (user request 2026-11-10: "looks ugly on an ebook reader"):** `design.md` rewritten. `app/bubbly.dart` became `app/press.dart` (`Pressable`, `ProgressLine`); the bubble splash, spring curve, morphing button shapes, wavy progress and tinted containers are gone. Covers without a picture use `bookCloth` colours.
- **Browse lists and catalogs in Find (user request 2026-11-10, after the Readexa app):** each source can offer lists (`BookSource.shelves`/`browse`): Gutenberg's own Popular / Latest / Random (its OPDS `sort_order`), the Archive's Most downloaded / Recently added. Users can add any OPDS catalog by https link (`find/opds_source.dart`, kept in setting `find_catalogs`): sections become lists, its search is used when it publishes one, only free (`acquisition` or `open-access`) EPUB/PDF links are offered. Adding a catalog adds its host, and the hosts of files it links to, to the allowed list; https is still required. Book covers in lists are drawn, not downloaded, so a list costs one request. Results open a details sheet with one Get button (Readexa shows three identical download buttons).
- **Book details from Open Library, not Goodreads (user asked for Goodreads ratings, 2026-11-10):** Goodreads closed its public API in 2020 and its terms forbid scraping. Open Library (`openlibrary.org`, added to `findHosts`) gives community ratings, want-to-read counts, first-published year, pages, subjects, description and covers. Looked up only when a book's details are opened (search, then the work; the cover through the same strict client), remembered per book. Matched by title and author, so the sheet says the details may describe another edition (e.g. The Story of an Hour's "first published" came back as 2014).
- **Download progress:** `FindService.download` reports bytes and total; the details sheet and a tray at the bottom of Find show MB, percent and "Adding to your library…".
- **Fewer, quieter colours (user request 2026-11-10: "hate the settings page and themes"):** `AppPalette` cut from eleven to five (indigo, forest, clay, plum, ink); a saved colour that no longer exists falls back to Indigo. `schemeFor` maps primary/secondary/tertiary containers to neutral surfaces, so tonal buttons and chips are never tinted. Text fields are outlined (they were invisible on dialogs: same fill as the dialog).
- **Shelf columns:** three on every phone width (under 600 dp), at the user's request; more only on tablets.
- **Bottom dock replaces the top Find and Settings buttons (user picked option C of four, 2026-11-10):** `app/home_shell.dart` holds Shelf, Find and Settings in an `IndexedStack` under one route, so each keeps its state. A now-playing strip above the dock opens Listen. `FindScreen(active:, onExit:)` handles back inside its lists only while it is the visible tab; back from Settings returns to the shelf. `openFind`/`openSettings` still exist for Listen and the reader.
- **Scrub guard removed (user: "tap again to jump... annoying every time we scrub"):** `ScrubGuard` and its test are deleted; a drag on the scrubber seeks straight away. Accidental jumps are undone instead: after a jump of 30 s or more, "Back to 12:40" shows for 8 s. The book slider in the reader does the same with the previous page (10 s).
- **My places:** places can be named (DB v4 adds `marks.note`) and removing has Undo.
- **Page/audio sync removed (user, 2026-11-10: "99% of the time inaccurate"):** `sync_map.dart`, the estimate and the "Line up page and audio" section are gone. Old `synced` rows stay in `marks`, hidden. Revisit only with a real method (e.g. a transcript).
- **One sample story (user, 2026-11-10):** only The Story of an Hour ships (about 1.4 MB audio); the other two were removed to cut size. Most of the ~130 MB is not samples: a profile APK is fat (three ABIs) and unshrunk, and Android's App size also counts added books. Sideload with `flutter build apk --split-per-abi --release`; Play's AAB is split per device.
- **Covers from Open Library (user asked for a "TMDB for book covers"):** `find/cover_source.dart` finds the work, then `/works/…/editions.json`, and offers every edition's cover (`covers.openlibrary.org`, M for the grid, L when chosen), through the strict `Web` client; a picture must be a real JPEG/PNG over 2 KB (Open Library's blank placeholder is tiny). Picker: `features/library/cover_picker.dart`, from Edit book, the book options and About this book. Google Books was tried and dropped: without an API key it shares one global daily quota and answered 429 in testing.
- **Covers and details for Find downloads:** after a download, `keepFindDetails` saves what Find showed (`book_details`, DB v5) and, for Gutenberg and Wikisource (plain generated covers) or a book with none, sets Open Library's cover. It runs in the background and never fails the download. The user's own files never go online by themselves; About this book offers Look up details and the cover picker.
- **Unglue.it added as a built-in source:** its OPDS catalog of free, openly licensed EPUBs (`open-access` links); robots.txt allows `/api/` for ordinary clients. No search, lists only. Its lists take 7–30 s to build, so it gets a 45 s read time and its blurb says so. Files come from `files.unglue.it` or `archive.org`; a book hosted elsewhere is refused by the host rules.
- **Sources checked and not added (2026-11-10):** Feedbooks (Cloudflare 403 to clients, robots.txt disallows all), gutenberg.ca (now a members-only library), Faded Page and Project Gutenberg Australia (no catalog feed; would need HTML scraping).
- **Recent searches:** the last six book searches are kept in setting `recent_searches` (all books share them), saved when a result is opened.
- **Store art uses only public domain covers:** first editions from Wikimedia Commons, each checked as "Public domain" there (`docs/store/covers/CREDITS.md`). Never use a modern cover or a bestseller's title in store images.
- **Signature footer:** only the scaled white PNG (`assets/brand/signature.png`) ships; `assets/ornob-aadi-signature/` is the source set and is not bundled.
- **Release signing:** `android/key.properties` (not committed) selects the upload key; without it, release builds use the debug key.
